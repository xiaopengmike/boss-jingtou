# M0 取证操作手册（接口考古）

> 镜像参考扩展的 "Phase 0 POC 接口考古"。**这一步没做完，后面全是猜。**
> 预计 30–60 分钟，需要你本人登录 BOSS 账号操作。

## 准备

1. `chrome://extensions` → 开发者模式 → 「加载已解压的扩展程序」→ 选 `boss-jingtou/` 目录
2. 打开扩展「设置」页，确认 **M0 取证模式（pocMode）已开启**（默认开）
3. 登录 BOSS 直聘网页端（www.zhipin.com）

## 操作路径（按顺序，每步停留 5–10 秒让接口跑完）

1. 打开职位搜索页，搜一个你的目标关键词（如「IT经理」「数字化」），翻 2–3 页
2. 点开 1 个职位详情页，**先不点沟通**，停留观察
3. 点「立即沟通」——**这一步最关键，盯住页面**：
   - 是直接跳到了聊天页（URL 变成 `/web/chat/...`）？
   - 还是弹出了一个确认/编辑框？
   - 输入框里有没有预置的默认招呼语？
4. 在聊天页手动发一句话，观察发出后消息是否立刻出现在聊天记录里
5. 回到 popup → 「导出缓冲 JSON」，把文件存好

## 必须回答的 9 个问题（对着导出的 JSON 逐项填）

| # | 问题 | 答案 | 影响 |
|---|---|---|---|
| 1 | 列表接口路径与结构？分页参数？ | | 校准 `jt_rules.listUrlIncludes` |
| 2 | 「立即沟通」按钮 DOM 特征（文本/层级）？已沟通态文案？ | | 校准 `greetTexts/greetedTexts` |
| 3 | 点击后走哪条分支：跳聊天页 / 弹窗 / 编辑框？ | | 决定 greeter 主分支 |
| 4 | 首次沟通是否强制弹窗？能否跳过？有默认话术吗？ | | 决定 chat-sender 是否需先关弹窗 |
| 5 | 聊天页输入框是 contenteditable 还是 textarea？发送按钮文本？ | | 校准 `editorSelectors/sendBtnTexts` |
| 6 | 发送走哪个接口？成功响应形态（code/zpData.rescode）？ | | 双成功判定，防 HTTP 200 业务失败 |
| 7 | 静默失效的可观测特征？（消息是否落聊天历史、有无"操作频繁"提示） | | 落库校验的判据 |
| 8 | 接口是否依赖签名参数（如 `__zp_stoken__`）？ | | 若签名 → 放弃接口重放，坚持 DOM 驱动 |
| 9 | 有没有"今日剩余沟通次数"额度接口/入口？（找 remain/quota/limit/leftCount 字样） | | 有 → 闸门接真实剩余额度；无 → 用本地计数 |

## 取证完成后

1. 把答案和导出的 JSON 交给 WorkBuddy，据此校准 `jt_rules`（设置页可改，不用动代码）
2. **关闭 pocMode**（设置页），扩展切换为只记录含职位特征的响应
3. 进入灰度爬坡：档0（5条/天）连跑 3 天无异常 → 人工升档

## 灰度档位表

| 档 | 日上限 | 升档条件 |
|---|---|---|
| 0 | 5 | 连跑 3 天：无验证码、无 suspected_silent、无熔断 |
| 1 | 20 | 同上 |
| 2 | 50 | 同上，且回复率无明显下滑 |
| 3 | 100 | 用户手动放行 |
